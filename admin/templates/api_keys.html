How keys work
  • A key starts with {{ key_prefix }}. Send it in the Authorization: Bearer header.
  • A key is shown once, when you create it. Only a fingerprint of it is stored, so nobody can read it back, including here.
  • Each key has its own conversations: one key cannot read or continue another key's chats.
  • Revoking takes effect on the key's next request. A revoked key cannot be turned back on.
  • Creating and revoking keys is recorded in Activity.
