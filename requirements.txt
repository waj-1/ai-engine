# Observability + evals — self-hosted Laminar (lmnr-ai/lmnr, Apache-2.0).
# OTel-native: Laminar.initialize() auto-instruments LangChain/LangGraph and
# every supported LLM provider (OpenAI, Anthropic, Gemini, …). Point the
# SDK at the docker-compose stack with LMNR_BASE_URL / LMNR_HTTP_PORT /
# LMNR_GRPC_PORT and a project API key from the local dashboard at :5667.
#
# Floor is 0.7.43. lmnr 0.7.42 constrained opentelemetry-instrumentation-langchain
# to >=0.47.1,<0.48.0 while leaving opentelemetry-api unbounded above. The 0.47.x
# instrumentor does `from opentelemetry._events import get_event_logger`, and that
# module was deleted in opentelemetry-api 1.44.0 (released 2026-07-16). Once a
# rebuild's resolver drifted onto 1.44.0, lmnr's instrumentor loop raised
# ModuleNotFoundError for `langchain` and `openai`, caught it, and booted with those
# two instrumentors silently disabled — killing every per-tool (`*.tool`) and
# `ChatGoogleGenerativeAI.chat` span in prod on 2026-07-21 while the LLM-level spans
# kept working. 0.7.43 pins opentelemetry-instrumentation-langchain==0.52.4, which
# has no `opentelemetry._events` import at all.
lmnr[all]==0.7.43
# The OTel core is pinned explicitly because it is otherwise purely transitive via
# lmnr and re-resolves on every image rebuild — that silent roll-forward is what
# caused the outage above. These are the versions lmnr 0.7.43 already forces (it
# pins semantic-conventions==0.60b1, which pins opentelemetry-api==1.39.1, which
# in turn forces opentelemetry-instrumentation==0.60b1). Stating them here makes
# the coupling visible and turns a future lmnr bump that moves the OTel floor into
# a loud resolver conflict instead of another silent drift.
opentelemetry-api==1.39.1
opentelemetry-sdk==1.39.1
opentelemetry-semantic-conventions==0.60b1
# wrapt 2.x made wrap_function_wrapper's `module` argument positional-only,
# which the OTel/lmnr auto-instrumentors call as a kwarg — breaking Laminar
# trace emission ("wrap_function_wrapper() got an unexpected keyword argument
# 'module'"). Pin to 1.x until the bundled instrumentors catch up.
# Still unfixed upstream: instrumentation-langchain 0.52.4 continues to call
# wrap_function_wrapper(module="langchain_core.callbacks", ...). The pinned
# opentelemetry-instrumentation 0.60b1 happens to cap wrapt<2 itself, but newer
# ones (0.65b0) relax that to wrapt<3 — so this pin stays the durable guard.
# TODO: drop this pin once lmnr[all]/opentelemetry instrumentors support wrapt 2
# (re-test trace emission end-to-end after unpinning).
